# Internationalization Guidelines — Frontend
version: 1.0
last-updated: 2026-06
changelog:
  - 1.0: initial version

## When to use this skill
When adding text to the UI, creating new translation keys,
or handling language-specific behavior.

## Why
All user-facing text must be translatable from day one.
Hardcoded strings create technical debt that is painful
to fix later and impossible to scale to new markets.

## Rules

### Never hardcode user-facing strings
ALWAYS use the `t()` function from i18next.

✅
```typescript
<Text>{t('confirmation.title')}</Text>
<Text>{t('common.error')}</Text>
Alert.alert(t('common.error'), t('recording.errorDetail'));
```

❌
```typescript
<Text>Confirm debt</Text>
<Text>Error</Text>
Alert.alert('Error', 'Something went wrong');
```

### Always add keys to both language files simultaneously
When you add a key to `en.json`, add it to `vi.json` in the
same operation. Never leave one file missing a key.

✅ Both files updated together:
```json
// en.json
{ "confirmation": { "title": "Confirm Debt" } }

// vi.json
{ "confirmation": { "title": "Xác nhận khoản nợ" } }
```

❌ Only one file updated:
```json
// en.json — updated
{ "confirmation": { "title": "Confirm Debt" } }

// vi.json — missing key ← NEVER
```

### Key naming convention
Use dot notation with two levels: `section.key`
Section names in camelCase, key names in camelCase.

✅
```
common.error
common.cancel
confirmation.title
recording.startButton
partialPayment.remainingBalance
```

❌
```
Error ← no section
confirmation_title ← underscore not dot
Confirmation.Title ← PascalCase
```

### Interpolation for dynamic values
Use `{{variable}}` syntax for dynamic content.

✅
```json
// en.json
{ "pending": { "confirmPayment": "Mark {{amount}} as paid?" } }
```

```typescript
t('pending.confirmPayment', { amount: formatAmount(debt.amount) })
```

❌
```typescript
`Mark ${formatAmount(debt.amount)} as paid?` ← hardcoded template
```

### Backend-generated messages in Vietnamese
Messages generated by the backend for Vietnamese merchants
can stay in Vietnamese — they are intentionally not translated
since the target user is always Vietnamese.

✅ Leave backend Vietnamese messages as-is:
```typescript
// Backend returns: "Bạn còn nợ 500.000 VND"
// No need to translate this
```

### Language detection
Detect the device language automatically on first launch.
Fall back to English if the language is not supported.

```typescript
lng: savedLanguage ?? (deviceLanguage === 'vi' ? 'vi' : 'en'),
fallbackLng: 'en',
```

## Translation key reference structure
```json
{
  "common": { "error", "cancel", "confirm", "save", "warning" },
  "login": { "title", "subtitle", "googleBtn", "errorGeneric" },
  "recording": { "tapToRecord", "tapToStop", "recording", ... },
  "confirmation": { "title", "amount", "date", "note", ... },
  "pending": { "title", "empty", "share", "markPaid", ... },
  "partialPayment": { "title", "amountLabel", "remainingBalance", ... },
  "subscription": { "title", "subtitle", "contact", "verify", ... },
  "errors": { "network", "server", "unauthorized", "notFound", ... }
}
```

## Checklist
- [ ] No hardcoded strings in UI or Alert calls
- [ ] t() used for all user-facing text
- [ ] New keys added to en.json AND vi.json simultaneously
- [ ] Key names follow section.key convention in camelCase
- [ ] Dynamic values use {{variable}} interpolation
- [ ] Fallback language is English
